# Brand contracts and registry

`brand-registry.json` selects source-backed distribution assets with SHA-256, canonical IDs, versions, phase ownership and intended platforms. `source-manifest.json` is the controlled repository inventory of 194 source artifacts, including supplemental historical evidence and V1.4.1. The immutable original manifest and its 133 entries remain independently pinned; both horizontal release manifests are pinned and checked. Observed historical files are inventory records, not newly approved assets. `source-inventory.json` covers every supplied artifact, including source-only history/evidence. `UNUSED_AT_AUDIT` describes the original absence of app consumers, not approval to delete the source.

`canonical/` preserves phase JSON specification and QA files verbatim. These are **presentation references, not API contracts or backend DTOs**. `REFERENCE_ONLY` records are not executable token exports. Earlier candidate labels are retained; user instruction and source README establish the production lock. Final specification/validation takes precedence over earlier candidate values. No new approval, rights, creator or historical provenance is asserted.

Registry platform usage indicates intended eligibility, not completed integration or platform QA. `FOUNDATION_ONLY` is deliberate: no Web/Mobile/Admin application exists. Horizontal light/dark/mono V1.4.1 is available; unsupported icon variants remain blocked. No exception or design re-open is granted here.

Pass #2 records foundation readiness separately: `READY_WITH_CANONICAL_ASSET_GAPS`; application integration: `NOT_STARTED — NO APPLICATION CONSUMERS PRESENT`. The original 36 resource records retain their identity/path/checksum. Three V1.4.1 horizontal assets bring the registry to 39 records. The horizontal gap is RESOLVED with three canonical IDs; seven actionable design gaps and three governed 16px micro requirements remain. Gap records are requirements, not fictitious assets, and have no production path or checksum. The existing V1.4 app icon uses `APPROVED_DERIVATIVE` based on its supplied production validation; no new derivative was generated. See `../../docs/brand/brand-asset-gap-matrix.md` for supported themes/sizes and all semantic glyphs.

Media presentation follows Phase 07: render only an explicitly supplied correct entity relation, media identity, classification, source, rights, editorial status and relevant disclosure/transform history. If unavailable, show a text-only no-media state and record `BACKEND_DEPENDENCY`; do not infer fields, scan directories, choose lookalikes or invent metadata. AI-generated media is never evidence. This package does not enforce publishing or change CMS/media APIs.

Phases 08–11 preserve platform accessibility, historical uncertainty, source access, truthful marketing and governance. Refer to their supplied JSON and original Markdown for full rules. Native exports and marketing assets are derivatives; never edit or promote them as new masters.

The drift gate is `node scripts/brand/validate.mjs`. It is backend-independent and read-only. Run it with `node --test scripts/brand/validate.test.mjs` for the isolated validator/resolver tests. It is not a substitute for browser/native rendering, accessibility or provenance QA.

Also run `powershell -NoProfile -File scripts/brand/validate-svg.ps1 -SelfTest` from the repository root. This local .NET XML check rejects malformed XML, DTDs, unsafe elements/attributes, broken internal references, invalid viewBoxes and incorrect sprite paint/label contracts. It neither fetches external resources nor changes SVGs. It validates the supplied static SVG subset, not arbitrary SVG features or rendered pixel contrast.
